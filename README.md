# Призрак (Prizrak) — «живая невидимость»

Android-приложение на Kotlin + Jetpack Compose: наводишь камеру на человека, касаешься
его на экране — приложение запоминает именно его. Дальше, пока эффект включён, этот
человек не виден на экране: вместо него в реальном времени подставляется то, что было
видно на его месте секунду-другую назад, а всё остальное в кадре идёт вживую.

## Как это работает

1. **Выбор цели** — тап по человеку на экране. По тапу берётся человек, чей bounding box
   (из MediaPipe Pose Landmarker) содержит точку тапа, и запоминается как цель: позиция,
   размер, примерный цвет одежды (сэмплируется в районе плеч/бёдер).
2. **Трекинг именно этого человека** — каждый кадр Pose Landmarker находит всех людей
   в кадре (до 4), и цель кадр за кадром сопоставляется с одним из них по близости
   позиции + похожести размера + похожести цвета одежды. Это эвристика, а не настоящая
   ре-идентификация: если два похоже одетых человека быстро поменяются местами, трекер
   может «перескочить».
3. **Маска человека** — MediaPipe Selfie Multiclass Segmentation даёт маску «любой
   человек» на кадре; она пересекается с областью вокруг bounding box отслеживаемой цели,
   чтобы получить маску именно её (а не всех людей в кадре).
4. **Восстановление фона (ядро эффекта)** — буфер последних ~12 кадров + их масок. Для
   каждого пикселя на месте цели ищется недавний кадр, где в этом же месте фона человек
   ещё не стоял; при движении камеры область старого кадра выравнивается под текущий
   ракурс через OpenCV (оптический поток / ORB + гомография — см. режимы ниже). Если
   ни один кадр в буфере не содержит чистого фона на этом месте (человек ещё не
   сдвигался, буфер только наполняется) — остаток докрашивается через
   `Photo.inpaint` (Telea), чтобы не было чёрной дыры, ценой размытия.

## Режимы компенсации движения камеры (этапы из ТЗ)

Переключаются прямо в интерфейсе, пока эффект активен:

- **Статично** — без компенсации сдвига, буфер используется как есть. Самый чистый
  результат, но только пока камера действительно не двигается (штатив / рука лежит).
- **Компенсация дрожания** — `goodFeaturesToTrack` + `calcOpticalFlowPyrLK` между кадром
  из буфера и текущим, затем `estimateAffinePartial2D` (сдвиг/поворот/масштаб). Дешёво,
  спасает от дрожания руки, ломается при резком повороте камеры.
- **Полная компенсация (бета)** — ORB-фичи + brute-force матчинг + `findHomography`
  (RANSAC). Работает при более заметном движении камеры, но тяжелее и чувствительна к
  сценам без текстуры (гладкая стена, темнота). При неудаче падает обратно на режим
  «Компенсация дрожания» для этого кадра.

## Честно о статусе

Как и предупреждено в задаче: real-time video inpainting на телефоне даёт заметные
артефакты, особенно при активном движении камеры — это не голливудский эффект, а
рабочий fun-прототип «магии» для коротких роликов. Конкретные ограничения:

- Трекинг цели — это сопоставление по позиции/размеру/цвету, а не настоящая
  ре-идентификация человека; в сложных сценах (несколько похоже одетых людей,
  пересечение целей) трекер может ошибиться.
- «Полная компенсация» — экспериментальный режим; в сценах без текстуры или при очень
  резком движении оценка гомографии может не найтись вовсе (эффект в этом кадре просто
  использует статичный буфер как есть).
- Первая пара секунд после нажатия «Старт» — фон ещё не накоплен в буфере, поэтому на
  месте человека возможен размытый (`inpaint`) заполнитель, а не «настоящий» фон.
- Работает только с задней камерой; фронтальную камеру и её зеркалирование пока не
  добавлял.

## Стек

Kotlin, Jetpack Compose, CameraX (`ImageAnalysis`, без `Preview` — картинка рисуется
напрямую на `SurfaceView`, чтобы можно было подменять пиксели до вывода на экран),
MediaPipe Tasks Vision (Pose Landmarker + Selfie Multiclass Segmentation), OpenCV for
Android (оптический поток, ORB, гомография, inpaint). `minSdk 24`.

## Сборка APK через GitHub Actions (без Android Studio)

1. Вкладка **Actions** в репозитории → **Build APK** → **Run workflow** (или просто
   запушь в `main` — соберётся автоматически). Workflow сам скачивает две модели
   MediaPipe (Pose Landmarker Lite и Selfie Multiclass Segmenter, суммарно ~15–20 МБ) —
   они не хранятся в репозитории.
2. Зайди в конкретный run → **Artifacts** → скачай `prizrak-debug-apk.zip`, внутри —
   `app-debug.apk`.
3. Установи APK на телефон (разреши установку из неизвестных источников).

## Локальная сборка в Android Studio (опционально)

Скачай модели вручную и положи в `app/src/main/assets/models/`:

```
https://storage.googleapis.com/mediapipe-models/pose_landmarker/pose_landmarker_lite/float16/latest/pose_landmarker_lite.task
https://storage.googleapis.com/mediapipe-models/image_segmenter/selfie_multiclass_256x256/float32/latest/selfie_multiclass_256x256.tflite
```

## Это собрано без доступа к Android SDK/эмулятору

Как и в других моих Android-проектах — весь код написан за один проход без возможности
локально скомпилировать и потестировать на устройстве. Первая сборка в Actions может
упасть на нюансах версий MediaPipe/OpenCV/Compose — если так, пришли текст ошибки
(вкладка Actions → неудачный run → раскрыть шаг с крестиком), поправлю точечно.

## Дальнейшее развитие

- Настоящая ре-идентификация цели (эмбеддинги внешности вместо цвет+позиция+размер).
- Фронтальная камера + зеркалирование превью.
- Инкрементальная оценка движения камеры (одна оценка на кадр вместо повторной оценки
  относительно каждого кадра в буфере) — быстрее и точнее при длительном движении.
- Запись результата в видеофайл, а не только live-просмотр.
